## 0. Hard constraints, restated so they survive to the coder

- **npm, not pnpm.** pnpm is not installed. Lockfile is `package-lock.json`. **Node 26**, pinned in `.nvmrc` and `package.json` `engines`.
- **Tailwind CSS v4, CSS-first.** All theme tokens live in the `@theme` block in `app/globals.css`. **There is no `tailwind.config.js` and you must not create one.** PostCSS uses `@tailwindcss/postcss`.
- **The browser NEVER talks to Supabase.** No `@supabase/supabase-js` import in any Client Component, any file under `components/`, `public/sw.js`, or any file with `'use client'`. The browser only calls this app's own route handlers under `/api/*`. Supabase and Kong are ClusterIP-only.
- **Service role key is server-only.** No environment variable in this project is ever prefixed `NEXT_PUBLIC_`. `lib/supabase/server.ts` starts with `import 'server-only';`.
- **Polling, never Supabase Realtime.** No websockets to Supabase. Poll interval 3000 ms.
- **`games.locked_rows` is game-wide colour closure.** It records which player closed each colour for everyone. **`sheets.locks` is one player's own lock mark and the points it earns.** These are different things. Never read one where the other is meant. Never derive one from the other except in the single place specified in section 4.5.
- **Out of scope, do not build:** dice roller, Qwixx variants (Gemischt, Connected, Big Points), OIDC / Authentik SSO, Supabase Realtime, spectator mode, chat, push notifications.
- **Copy standard.** All user-facing text uses short active sentences. No em dashes, no en dashes, no semicolons, no hyphen chains. No hype words. No emoji in shipped UI copy.
- **Accessibility is a gate.** WCAG 2.2 AA. Colour is never the only signal for the four rows or for any state.

## 2. `lib/scoring.ts`, the pure scoring module

**This module is written and its tests pass before any UI file is created.** It imports nothing except types from `lib/types.ts`. It must not:

- import React or anything from `next/*`
- perform network calls
- call `Date.now()`, `new Date()`, `performance.now()`
- call `Math.random()` or `crypto`
- mutate any argument

Every function returns new objects. Freeze inputs in tests to prove it.

### 2.1 Row model

A row has 11 numbers. Positions are stored as a zero-based **index 0 to 10 measured left to right along the printed row**, which normalises the two directions. Never store the printed number.

| Colour | Direction | index 0 | index 10 |
|---|---|---|---|
| red | ascending | 2 | 12 |
| yellow | ascending | 2 | 12 |
| green | descending | 12 | 2 |
| blue | descending | 12 | 2 |

`LOCK_INDEX = 10` for all four rows. That is the cell whose cross can trigger a lock.

### 2.2 Constants and exports

```ts
export type Color = 'red' | 'yellow' | 'green' | 'blue';
export const COLORS: readonly Color[];              // ['red','yellow','green','blue'] in that order
export const ROW_LENGTH = 11;
export const LOCK_INDEX = 10;
export const MAX_PENALTIES = 4;
export const PENALTY_POINTS = -5;                    // per penalty
export const MIN_CROSSES_TO_LOCK = 5;                // crosses required BEFORE crossing LOCK_INDEX
export const LOCKS_TO_END_GAME = 2;
```

### 2.3 Types

```ts
export interface Sheet {
  crosses: Record<Color, number[]>;   // ascending, unique, each 0..10
  locks: Record<Color, boolean>;      // THIS player's lock mark. Scores as one extra mark.
  penalties: number;                  // 0..4
}

export type LockedRows = Record<Color, string | null>; // game-wide. playerId of the first locker, or null.

export interface PlayerState {
  playerId: string;
  seat: number;
  sheet: Sheet;
}

export interface GameState {
  players: PlayerState[];
  lockedRows: LockedRows;
}

export interface SheetScore {
  rows: Record<Color, number>;
  rowsTotal: number;
  penaltyPoints: number;   // negative or zero
  total: number;           // rowsTotal + penaltyPoints
}

export type RejectReason =
  | 'out_of_range'
  | 'row_closed'
  | 'not_strictly_right'
  | 'lock_requires_five'
  | 'max_penalties'
  | 'nothing_to_undo';

export type Legality =
  | { ok: true; locksRow: boolean }
  | { ok: false; reason: RejectReason };

export type EndReason = 'penalties' | 'two_locks';

export interface Standing {
  playerId: string;
  seat: number;
  rows: Record<Color, number>;
  total: number;
  penalties: number;
  bestRowCrosses: number;   // max crosses in a single row. The lock mark is NOT counted here.
  rank: number;             // 1-based. Tied players share a rank.
}
```

### 2.4 Function signatures and exact semantics

```ts
export function numberAt(color: Color, index: number): number;
```
Ascending rows return `index + 2`. Descending rows return `12 - index`. Throws `RangeError` if index is outside 0..10.

```ts
export function indexOfNumber(color: Color, value: number): number;
```
Inverse of `numberAt`. Returns -1 if `value` is outside 2..12.

```ts
export function triangular(n: number): number;
```
Returns `(n * (n + 1)) / 2`. `triangular(0) === 0`. Throws `RangeError` if `n < 0` or `n > 12`.

```ts
export function scoreRow(crossCount: number, locked: boolean): number;
```
Returns `triangular(crossCount + (locked ? 1 : 0))`.

**The lock is an extra mark, not a flat plus one point.** This is regression bug 1 from the old app. `scoreRow(5, true) === 21`, not 16.

```ts
export function emptySheet(): Sheet;
```
All four rows empty, all four locks false, penalties 0.

```ts
export function emptyLockedRows(): LockedRows;
```
All four colours null.

```ts
export function crossCount(sheet: Sheet, color: Color): number;
```
Length of `sheet.crosses[color]`. The lock mark is not included.

```ts
export function rightmostIndex(sheet: Sheet, color: Color): number;
```
Largest crossed index in that row, or `-1` when the row is empty.

```ts
export function scoreSheet(sheet: Sheet): SheetScore;
```
`rows[c] = scoreRow(crossCount(sheet, c), sheet.locks[c])`. `rowsTotal` is their sum. `penaltyPoints = sheet.penalties * PENALTY_POINTS` (so it is negative or zero). `total = rowsTotal + penaltyPoints`.

```ts
export function canCross(sheet: Sheet, lockedRows: LockedRows, color: Color, index: number): Legality;
```
Checks in this exact order and returns the first failure:

1. `index` is an integer in 0..10, else `out_of_range`.
2. `lockedRows[color] !== null`, else `row_closed`. **The row is closed game-wide for everyone, including the player who closed it.**
3. `index > rightmostIndex(sheet, color)`, else `not_strictly_right`. Re-crossing an existing cell and crossing the current rightmost both fail here. This is regression bug 2.
4. If `index === LOCK_INDEX`, then `crossCount(sheet, color) >= MIN_CROSSES_TO_LOCK`, else `lock_requires_five`. This is regression bug 3. Five crosses must already be held **before** this cross.

On success returns `{ ok: true, locksRow: index === LOCK_INDEX }`.

```ts
export function applyCross(
  sheet: Sheet, lockedRows: LockedRows, color: Color, index: number, playerId: string
): { sheet: Sheet; lockedRows: LockedRows; lockedNow: boolean };
```
Calls `canCross` first. Throws `new Error(reason)` if illegal. Otherwise returns new objects where:
- `sheet.crosses[color]` has `index` appended and the array stays ascending.
- If `index === LOCK_INDEX`: `sheet.locks[color] = true` and `lockedRows[color] = playerId`. `lockedNow` is true.
- Otherwise `lockedNow` is false and `lockedRows` is returned unchanged by value.

Note the ordering: `canCross` step 2 already guarantees `lockedRows[color]` was null, so the first legal locker is always the one recorded.

```ts
export function canPenalty(sheet: Sheet): Legality;
```
`{ ok: false, reason: 'max_penalties' }` when `sheet.penalties >= MAX_PENALTIES`, else `{ ok: true, locksRow: false }`.

```ts
export function applyPenalty(sheet: Sheet): Sheet;
```
Returns a new sheet with `penalties + 1`. Throws if already at 4.

```ts
export function canUndoCross(sheet: Sheet, color: Color, index: number): boolean;
```
True only when `index === rightmostIndex(sheet, color)` and the row is not empty. Only the last cross in a row may be removed.

```ts
export function undoCross(
  sheet: Sheet, lockedRows: LockedRows, color: Color, index: number, playerId: string
): { sheet: Sheet; lockedRows: LockedRows };
```
Throws if `canUndoCross` is false. Removes the index. If `index === LOCK_INDEX`, sets `sheet.locks[color] = false`, and clears `lockedRows[color]` to null **only when `lockedRows[color] === playerId`**. If another player owns the game-wide closure, leave it. That is the one place the two lock concepts touch.

```ts
export function undoPenalty(sheet: Sheet): Sheet;
```
Throws when `penalties === 0`. Otherwise returns a new sheet with `penalties - 1`.

```ts
export function lockedColorCount(lockedRows: LockedRows): number;
```
Count of colours whose value is not null.

```ts
export function checkGameEnd(state: GameState): { ended: boolean; reason: EndReason | null };
```
Ends when **any** player has `penalties >= MAX_PENALTIES`, reason `'penalties'`. Otherwise ends when `lockedColorCount(state.lockedRows) >= LOCKS_TO_END_GAME`, reason `'two_locks'`. Penalties are checked first, so a batch that produces both reports `'penalties'`. Otherwise `{ ended: false, reason: null }`. This is regression bug 4, which had no implementation at all in the old app.

```ts
export function rankPlayers(state: GameState): Standing[];
```
Builds a `Standing` per player, then sorts descending by the official tiebreakers in this order:

1. `total`, higher wins.
2. `penalties`, **fewer** wins.
3. `bestRowCrosses`, higher wins.
4. Fully tied players keep the same `rank`. Break the array order by ascending `seat` so the output is deterministic.

`bestRowCrosses` is `Math.max(...COLORS.map(c => crossCount(sheet, c)))`. **The lock mark is deliberately excluded.** The rulebook tiebreaker counts numbers crossed, and the lock symbol is not a number.

`rank` is 1-based and dense-shared: two fully tied players both get rank 1, the next gets rank 3.

```ts
export function resolveWinners(state: GameState): { winners: string[]; standings: Standing[] };
```
`standings` is the output of `rankPlayers`. `winners` is every `playerId` with `rank === 1`. Length 1 in the normal case. Length greater than 1 means a true tie after all three tiebreakers.

### 2.5 The 21 versus 28 point, read this before writing tests

Two different numbers appear in the source material and both are correct in their own context. Do not "fix" either.

- **`scoreRow` is a pure arithmetic function and enforces no legality.** `scoreRow(5, true) === 21` because `triangular(6) === 21`. This is the exact regression assertion named in the intent for bug 1. The old app returned 16.
- **A legal in-game lock needs five crosses already held before crossing index 10.** So the realistic end state is 6 crosses plus a lock, which is 7 marks, `triangular(7) === 28`.

Both are tested. `scoreRow` does not call `canCross` and `canCross` does not call `scoreRow`.

## 4. Route handlers

All route handlers set `export const runtime = 'nodejs'` and `export const dynamic = 'force-dynamic'`.

**Next.js 15 note that will otherwise cost you an hour:** dynamic params are a Promise. Every handler under `app/api/games/[code]/` is typed as:

```ts
export async function GET(req: Request, ctx: { params: Promise<{ code: string }> }) {
  const { code } = await ctx.params;
}
```

The same applies to `app/g/[code]/page.tsx`.

Request bodies are validated with `zod`. A schema failure returns 400 with `{ error: 'bad_request', detail: <zod flatten> }`.

### 4.0 Shared error envelope

Every non-2xx response is `{ error: string, message: string }` with these codes:

| HTTP | error | Meaning |
|---|---|---|
| 400 | `bad_request` | Body or params failed validation. |
| 401 | `no_device` | `qx_device` missing or its signature failed. |
| 403 | `not_seated` | Device holds no seat in this game. |
| 403 | `not_host` | Action requires seat 1. |
| 404 | `game_not_found` | Code did not resolve to a non-ended game. |
| 409 | `wrong_status` | Game is not in the status this action requires. |
| 409 | `version_conflict` | `baseVersion` did not match `sheets.version`. |
| 409 | `game_full` | Five seats already taken. |
| 422 | `mutation_rejected` | A mutation in the batch was illegal. Carries `index` and `reason`. |
| 429 | `rate_limited` | Join rate limit tripped. Carries `retryAfter` seconds. |
| 500 | `server_error` | Anything else. Never leak a Postgres message to the client. |

### 4.1 `GET /api/me`

Bootstrap the device. No body.

- **Cookie required:** none. Issues `qx_device` if absent.
- **Behaviour:** if `qx_device` is present and verifies, load `qwixx.players` for that id. If the row is missing, treat the cookie as invalid and issue a fresh one. If absent or invalid, insert a new `qwixx.players` row with `display_name` `'Player'` and set `qx_device`.
- **Response 200:**
  ```ts
  { playerId: string; displayName: string; activeSeat: { code: string; seat: number } | null }
  ```
  `activeSeat` is populated from the `qx_seat` cookie only when that game still resolves and its status is `lobby` or `active`. It powers the "rejoin with no prompt" requirement.
- **Errors:** 500 only.

### 4.2 `POST /api/games`

Create a game. The caller becomes the host at seat 1.

- **Cookie required:** `qx_device`. Issued here if absent, same logic as `/api/me`.
- **Request:** `{ displayName: string }`. Trimmed, 1 to 24 characters after trimming, no control characters.
- **Auth check:** device identity resolves to a `qwixx.players` row.
- **Behaviour, one transaction:**
  1. Update `qwixx.players.display_name` to the given name so it becomes the device default.
  2. Generate a join code per section 6. Insert `qwixx.games` with `status = 'lobby'`, `locked_rows` set to all four keys null.
  3. Insert `qwixx.game_players` with `seat = 1`, `claimed_at = now()`.
  4. Insert `qwixx.sheets` with an empty sheet, `penalties 0`, `version 0`.
- **Response 201:** `{ code: string; seat: 1; playerId: string }`. Sets `qx_seat` for this game.
- **Errors:** 401 `no_device` (cannot happen, we issue one), 400, 500.

### 4.3 `POST /api/games/join`

- **Cookie required:** `qx_device`. Issued here if absent.
- **Request:** `{ code: string; displayName: string }`. `code` is normalised per section 6 before lookup.
- **Rate limited.** See section 6.3. The rate limit check runs **before** any database read of `games`, so a scan for valid codes is throttled.
- **Auth check:** device identity resolves.
- **Behaviour, one transaction with `select ... from qwixx.games where join_code = $1 and status <> 'ended' for update`:**
  1. No row: 404 `game_not_found`. Return the same 404 whether the code never existed or the game ended, so the endpoint does not confirm code existence.
  2. `status = 'active'`: if this device already holds a seat in this game, re-issue `qx_seat` and return 200 with that seat. This is rejoin. Otherwise 409 `wrong_status` with message `This game has already started.` Late join is blocked.
  3. `status = 'lobby'`: if this device already holds a seat, update the display name and return that seat. Otherwise count seats. Five seats taken gives 409 `game_full`. Else take `max(seat) + 1`, insert `game_players` and an empty `sheets` row.
  4. Update `qwixx.players.display_name`.
- **Response 200:** `{ code: string; seat: number; playerId: string; status: 'lobby' | 'active' }`. Sets `qx_seat`.
- **Errors:** 400, 404, 409 `wrong_status`, 409 `game_full`, 429 `rate_limited`, 500.

### 4.4 `GET /api/games/[code]`

The single poll endpoint. It serves lobby state, active state and ended state. There is no separate lobby endpoint, because the client needs the same player list, status and identity in all three phases and one endpoint means one cache key and one reconciliation path.

- **Cookie required:** `qx_seat` for this code, or `qx_device` with a matching `game_players` row. See section 5.3 for seat resolution. A device with no seat in this game gets 403 `not_seated`. There is no spectator mode.
- **Request:** none. Supports the `If-None-Match` request header.
- **Behaviour:** load the game by `join_code`. For `status = 'ended'` the code no longer resolves for join, but this endpoint **does** serve an ended game to a seated device, because the players need to see the final board. Resolve by `join_code` including ended rows here.
  Compute an ETag as `W/"<status>:<lockedRowsHash>:<max(sheets.updated_at) epoch ms>:<player count>"`. If it matches `If-None-Match`, return 304 with no body.
- **Response 200:**
  ```ts
  {
    game: {
      code: string;
      status: 'lobby' | 'active' | 'ended';
      lockedRows: Record<Color, string | null>;
      endReason: 'penalties' | 'two_locks' | 'abandoned' | 'host_ended' | null;
      winnerPlayerId: string | null;   // null also means a tie. Recompute the tied set from standings.
      endedAt: string | null;
      hostPlayerId: string;            // the seat 1 player
    };
    you: { playerId: string; seat: number; displayName: string; version: number };
    players: Array<{
      playerId: string;
      seat: number;
      displayName: string;
      crosses: Record<Color, number[]>;
      locks: Record<Color, boolean>;
      penalties: number;
      version: number;
      rows: Record<Color, number>;   // computed with lib/scoring scoreSheet
      total: number;
      finalScore: number | null;
      updatedAt: string;
    }>;
    standings: Standing[] | null;      // non-null only when status is 'ended'
  }
  ```
  `players` is sorted by seat ascending.
- **Errors:** 401, 403 `not_seated`, 404, 500.
- **Cache headers:** `Cache-Control: no-store`.

### 4.5 `POST /api/games/[code]/start`

- **Cookie required:** `qx_seat` for this code and the resolved seat must be 1.
- **Request:** none.
- **Auth check:** seat resolution succeeds and `seat === 1`, else 403 `not_host`.
- **Behaviour:** `select ... for update` on the game. Status must be `lobby`, else 409 `wrong_status`. Player count must be 2 to 5, else 409 `wrong_status` with message `A game needs at least two players.` Set `status = 'active'`.
- **Response 200:** `{ status: 'active' }`.
- **Errors:** 401, 403 `not_seated`, 403 `not_host`, 404, 409, 500.

### 4.6 `POST /api/games/[code]/mutations`

The only write path for gameplay. It carries marks, penalties and undos. Marks, penalties and undos are three mutation types on one endpoint rather than three endpoints, because the local-first queue flushes an ordered batch and an ordered batch must be replayed in one transaction against one version.

- **Cookie required:** `qx_seat` for this code. Seat resolution must succeed. **The handler writes only the sheet named by the resolved `(gameId, playerId)`. The request body carries no player id at all, so a client cannot address another player's sheet.**
- **Request:**
  ```ts
  {
    baseVersion: number;             // the client's lastAckedVersion
    mutations: Array<
      | { id: string; type: 'mark';    color: Color; index: number }
      | { id: string; type: 'penalty' }
      | { id: string; type: 'undo';    undoes: { type: 'mark'; color: Color; index: number } | { type: 'penalty' } }
    >;
  }
  ```
  `id` is a client-generated UUID used for logging only. `mutations` has length 1 to 50. An empty array is a 400.
  An `undo` carries the full description of what it removes, so the server needs no move log table.
- **Behaviour, one transaction:**
  1. `select ... from qwixx.games where join_code = $1 for update`. Status must be `active`, else 409 `wrong_status`.
  2. `select ... from qwixx.sheets where game_id = $1 and player_id = $2 for update`.
  3. If `sheet.version !== baseVersion`, return **409 `version_conflict`** with the authoritative payload (see below). Apply nothing.
  4. Replay the batch in order against `{sheet, lockedRows}` using `lib/scoring.ts` only. `mark` uses `applyCross`, `penalty` uses `applyPenalty`, `undo` uses `undoCross` or `undoPenalty` after checking `canUndoCross`.
  5. **The batch is atomic.** If any mutation is illegal, roll back and return **422 `mutation_rejected`** with `{ index: <0-based position in the batch>, reason: RejectReason }` plus the authoritative payload. Atomicity is chosen so the sheet is always one consistent state and the client has exactly one reconciliation path.
  6. Write `sheets.crosses`, `sheets.locks`, `sheets.penalties`, `sheets.updated_at = now()`, `sheets.version = baseVersion + 1`. Write `games.locked_rows` if it changed.
  7. Run `checkGameEnd` over all players in the game. If ended, run the end-of-game write described in section 4.8 inside the same transaction.
- **Response 200:**
  ```ts
  {
    version: number;
    sheet: { crosses: Record<Color, number[]>; locks: Record<Color, boolean>; penalties: number };
    lockedRows: Record<Color, string | null>;
    gameStatus: 'active' | 'ended';
    endReason: EndReason | null;
  }
  ```
- **409 and 422 payload:** the same four fields (`version`, `sheet`, `lockedRows`, `gameStatus`) reflecting authoritative server state, plus the error envelope and, for 422, `index` and `reason`.
- **Errors:** 400, 401, 403 `not_seated`, 404, 409 `wrong_status`, 409 `version_conflict`, 422 `mutation_rejected`, 500.

### 4.7 `PATCH /api/games/[code]/player`

Rename this player inside this game. The display name is editable per game, per the intent.

- **Cookie required:** `qx_seat` for this code.
- **Request:** `{ displayName: string }`, 1 to 24 characters after trimming.
- **Behaviour:** game status must be `lobby` or `active`. Update `qwixx.players.display_name`, which also updates the device default for future games. Bump nothing on `sheets`.
- **Response 200:** `{ displayName: string }`.
- **Errors:** 400, 401, 403, 404, 409, 500.

### 4.8 `POST /api/games/[code]/end`

Host forces the game to end. The normal end path is automatic inside `/mutations` step 7. This endpoint exists so a host can stop a game the table has abandoned mid-session.

- **Cookie required:** `qx_seat` for this code, resolved seat 1, else 403 `not_host`.
- **Request:** none.
- **Behaviour:** status must be `active`, else 409 `wrong_status`. Run the shared end-of-game write with `end_reason = 'host_ended'`.
- **Shared end-of-game write (used here and by `/mutations` step 7):**
  1. Load every player's sheet.
  2. `const { winners, standings } = resolveWinners(state)`.
  3. Write `game_players.final_score` for every player from `standings`.
  4. Write `games.status = 'ended'`, `ended_at = now()`, `end_reason = <reason>`, and `winner_player_id = winners.length === 1 ? winners[0] : null`. **A null `winner_player_id` on an ended game means a tie.** The tied set is recomputed from `final_score` and the retained sheets, which are kept indefinitely.
- **Response 200:** `{ status: 'ended'; endReason: string; winnerPlayerId: string | null; standings: Standing[] }`.
- **Errors:** 401, 403 `not_seated`, 403 `not_host`, 404, 409, 500.

### 4.9 `GET /api/history`

- **Cookie required:** `qx_device`. `qx_seat` is not used here.
- **Request:** optional query `?limit=` default 50, max 100, and `?cursor=` an ISO `ended_at`.
- **Behaviour:** every `qwixx.games` row with `status = 'ended'` joined through `game_players` for this device's `player_id`. Ordered by `ended_at` descending. Abandoned games **are included** and flagged.
- **Response 200:**
  ```ts
  {
    games: Array<{
      gameId: string;
      code: string;
      endedAt: string;
      endReason: 'penalties' | 'two_locks' | 'abandoned' | 'host_ended';
      abandoned: boolean;                 // endReason === 'abandoned'
      winnerPlayerId: string | null;
      youWon: boolean;
      players: Array<{
        playerId: string; displayName: string; seat: number;
        finalScore: number | null;
        rows: Record<Color, number>;      // per row breakdown, computed from the retained sheet
        penalties: number;
      }>;
    }>;
    nextCursor: string | null;
  }
  ```
- **Errors:** 401, 500.

### 4.10 `GET /api/profile`

- **Cookie required:** `qx_device`.
- **Behaviour:** aggregate over ended games this device played **excluding `end_reason = 'abandoned'`**, per the intent. `host_ended` games do count, because they have a real winner and real scores.
- **Response 200:**

## 5. The two cookies

There are **two** cookies and they carry different things. Do not merge them and do not read one where the other is meant.

Both are signed with HMAC-SHA256 in `lib/cookies.ts` using `node:crypto`, keyed by `QWIXX_COOKIE_SECRET`. Format:

```
<base64url(JSON.stringify(payload))>.<base64url(hmacSha256(secret, base64urlPayload))>
```

Verification splits on the last `.`, recomputes the MAC, and compares with `crypto.timingSafeEqual`. A length mismatch fails before the compare. A failed verification is treated exactly like a missing cookie. No JWT library, no `jose`. Hand-rolled HMAC is chosen because the payloads are two and three fields and a JWT brings algorithm negotiation we do not want.

### 5.1 `qx_device`, the durable device-level player identity

| Property | Value |
|---|---|
| Name | `qx_device` |
| Payload | `{ "pid": "<uuid of qwixx.players.id>", "iat": <epoch seconds> }` |
| httpOnly | `true` |
| Secure | `true` |
| SameSite | `Lax` |
| Path | `/` |
| Max-Age | `63072000` (2 years) |

This cookie is the profile key. It is created on the first `/api/me`, `/api/games` or `/api/games/join` call from a device and reused for every later game, so lifetime stats accumulate. It is **never** scoped to a game. It carries no seat and no game id. Merging two devices into one profile is out of scope for v1.

### 5.2 `qx_seat`, the per-game seat claim

| Property | Value |
|---|---|
| Name | `qx_seat` |
| Payload | `{ "gid": "<uuid of qwixx.games.id>", "code": "<join code>", "pid": "<player id>", "seat": <1..5>, "iat": <epoch seconds> }` |
| httpOnly | `true` |
| Secure | `true` |
| SameSite | `Lax` |
| Path | `/` |
| Max-Age | `604800` (7 days) |

This cookie is the write authorisation for one game. It is set by create, join and rejoin. It holds one seat at a time. Joining a second game replaces it.

### 5.3 Seat resolution, `lib/auth.ts`

Because `qx_seat` holds only one game, a device returning to an earlier game would otherwise be locked out. Resolution therefore falls back to the durable identity.

```ts
export async function resolveDevice(req: Request):
  Promise<{ playerId: string; displayName: string } | null>;

export async function resolveSeat(req: Request, code: string):
  Promise<{ gameId: string; playerId: string; seat: number; setCookie: string | null } | null>;
```

`resolveSeat` steps:

1. Verify `qx_device`. If it fails, return null. The route returns 401 `no_device`.
2. Verify `qx_seat`. If it verifies and `payload.code === code` and `payload.pid === devicePlayerId`, use it. `setCookie` is null.
3. Otherwise query `qwixx.game_players` joined to `qwixx.games` for `(join_code = code, player_id = devicePlayerId)`. If a row exists, use it and set `setCookie` to a freshly signed `qx_seat` so the fast path works next time. The route must attach that `Set-Cookie` to its response.
4. No row: return null. The route returns 403 `not_seated`.

**`qx_seat.pid` is never trusted on its own.** It is only accepted when it equals the `qx_device` player id. That prevents a stolen or replayed seat cookie from writing on a device that does not hold the matching identity.

## 6. Join codes and the join rate limit

### 6.1 Alphabet

`lib/joincode.ts`:

```ts
export const ALPHABET = '23456789ABCDEFGHJKMNPQRSTVWXYZ';  // exactly 30 characters
export const CODE_LENGTH = 6;
```

That is the 26 letters minus `I`, `L`, `O`, `U`, and the 10 digits minus `0`, `1`. Thirty characters, so nothing is ambiguous read aloud in a room or typed on a phone keyboard. Add a unit test asserting `ALPHABET.length === 30` and that none of `I L O U 0 1` appears.

### 6.2 Generation and collision handling

```ts
export function generateJoinCode(): string;
export function normalizeJoinCode(input: string): string | null;
```

`generateJoinCode` uses `crypto.randomBytes` with **rejection sampling** to avoid modulo bias: draw a byte, discard it when it is `>= 240` (because `240 = 8 * 30` is the largest multiple of 30 below 256), otherwise take `byte % 30`. Repeat until 6 characters are drawn.

`normalizeJoinCode` uppercases, strips whitespace and hyphens, then maps the common misreads before validating: `I` and `L` to `1`? No. Map in the safe direction only: `0` to `O` is wrong because `O` is excluded. Map ambiguous input **into** the alphabet: `0` becomes nothing, `O` becomes nothing. Concretely, apply `I -> 1` is invalid too. **Rule: normalisation performs uppercase, removes whitespace and hyphens, and then rejects any string that is not exactly 6 characters all drawn from `ALPHABET`, returning null.** No character substitution at all. Substitution would create ambiguity in the opposite direction, which is the thing the alphabet exists to prevent. The UI compensates by rejecting excluded characters at input time with the message `Codes use only these characters: 23456789ABCDEFGHJKMNPQRSTVWXYZ`.

Collision handling: the unique partial index in section 7 makes uniqueness a database guarantee across all games that are not ended. `POST /api/games` generates a code and inserts. On unique violation (`23505`) it regenerates and retries, up to **5 attempts**, then returns 500 `server_error`. With 30^6 = 729,000,000 codes and a handful of live games, a second attempt will effectively never be needed.

Because the index is partial on `status <> 'ended'`, a code becomes reusable once its game ends, which is the intended behaviour: the code stops resolving for join at that moment.

### 6.3 Rate limit on the join endpoint

There is no Redis in the cluster and none is being stood up, so the counter lives in Postgres in `qwixx.rate_limits`. A fixed window counter is chosen over a sliding window because a single atomic upsert is enough and the traffic is a handful of people in one room.

- **Limits:** `10` join attempts per **60 second** window per key. Two keys are checked and both must pass:
  1. `ip:<hmacSha256(QWIXX_IP_HASH_SECRET, clientIp)>` at 10 per 60 s.
  2. `dev:<playerId>` at 20 per 60 s, applied only when `qx_device` verifies.
- **Client IP** comes from `cf-connecting-ip` first, then the first entry of `x-forwarded-for`, then `'unknown'`. Traffic arrives through the Cloudflare Tunnel so `cf-connecting-ip` is the reliable one. **The raw IP is never stored.** Only the HMAC is.
- **Window key:** `date_trunc('minute', now())`.
- **Atomic increment:**
  ```sql
  insert into qwixx.rate_limits (bucket_key, window_start, count)
  values ($1, date_trunc('minute', now()), 1)
  on conflict (bucket_key, window_start)
  do update set count = qwixx.rate_limits.count + 1
  returning count;
  ```
  If the returned count exceeds the limit, return 429 `rate_limited` with `retryAfter` equal to the seconds remaining in the window and a `Retry-After` response header. **The check runs before any `games` lookup**, so a code-guessing scan is throttled before it can probe.
- **Old windows** are deleted by the scheduled cleanup in section 7.3.

`lib/ratelimit.ts` signature:

```ts
export async function consume(bucketKey: string, limit: number): Promise<{ allowed: boolean; retryAfter: number }>;
```

### 7.2 Data model reminder that the migration encodes

`qwixx.games.locked_rows` is **game-wide colour closure**. Its value per colour is the player id of whoever closed it for everyone, or null. `qwixx.sheets.locks` is **one player's own lock mark**, a boolean, which is worth one extra mark in `scoreRow`. A player can have `sheets.locks.red = true` only when `games.locked_rows.red` names that same player, but the reverse is not a derivation you may perform in application code, because the closure also blocks every other player who has no lock mark.

### 7.3 `supabase/migrations/0002_cleanup_jobs.sql`

Implements the abandoned-game rules from Resolved since intake. Runs as a scheduled job, never on request.

```sql
create or replace function qwixx.cleanup_abandoned()
returns table (lobbies_deleted int, games_abandoned int, rate_rows_deleted int)
language plpgsql
security definer
set search_path = qwixx, public
as $$
declare
  l int; a int; r int;
begin
  -- A lobby with no start after 24 hours is deleted outright.
  with d as (
    delete from qwixx.games
    where status = 'lobby' and created_at < now() - interval '24 hours'
    returning 1
  ) select count(*)::int into l from d;

  -- An active game with no sheet write for 7 days is marked abandoned.
  with d as (
    update qwixx.games g
    set status = 'ended',
        ended_at = now(),
        end_reason = 'abandoned',
        winner_player_id = null
    where g.status = 'active'
      and coalesce(
            (select max(s.updated_at) from qwixx.sheets s where s.game_id = g.id),
            g.created_at
          ) < now() - interval '7 days'
    returning 1
  ) select count(*)::int into a from d;

  -- Rate limit windows older than one hour are dead weight.
  with d as (
    delete from qwixx.rate_limits
    where window_start < now() - interval '1 hour'
    returning 1
  ) select count(*)::int into r from d;

  return query select l, a, r;
end;
$$;

-- Hourly schedule. pg_cron is the simplest option that needs nothing new in the cluster.
create extension if not exists pg_cron;
select cron.schedule('qwixx-cleanup', '7 * * * *', $$select qwixx.cleanup_abandoned();$$);
```

Retention: games with `status = 'ended'` are kept **indefinitely**. That retention is the history feature. There is no purge job for them. Sheets are kept with them, which is what makes the per row breakdown in history and the `bestRow` stat in profile possible.

If `create extension pg_cron` fails on the target instance, the function still installs. Note that in the README and leave a k3s CronJob for the operator to wire. Do not add a request-time cleanup path.

## 8. Local-first sync design

Rendering never waits on the network. Every tap writes to IndexedDB and updates local state synchronously. The network is a background flush.

### 8.1 IndexedDB, `lib/idb.ts`

Database name `qwixx`, version `1`. Object stores:

| Store | keyPath | Contents |
|---|---|---|
| `meta` | `k` | Singletons. `{k:'device', playerId, displayName}`, `{k:'lastGame', code}`. |
| `snapshots` | `code` | The last successful poll response for a game, verbatim, plus `fetchedAt`. Drives opponent rendering and offline reopen. |
| `sheets` | `code` | This device's own sheet for one game: `{ code, serverSheet, lastAckedVersion, lockedRows, gameStatus }`. `serverSheet` is the last server-acknowledged state, not the rendered state. |
| `queue` | `seq` (autoIncrement) | Pending mutations: `{ seq, code, mutation, createdAt }`. Indexed on `code`. |
| `moves` | `seq` (autoIncrement) | Applied local move log per game for the undo button: `{ seq, code, kind: 'mark'|'penalty', color?, index?, undone: boolean }`. Indexed on `code`. |

`moves` exists because undo must know what the last mark was, and a sheet alone cannot say which of its four rightmost crosses was placed last.

### 8.2 Local truth

```
localSheet = replay(sheets[code].serverSheet, queue.filter(q => q.code === code) ordered by seq)
```

`replay` uses `lib/scoring.ts` and nothing else. `ScoreSheet` renders `localSheet`. `lockedRows` used for rendering is `sheets[code].lockedRows` with any lock produced by the queue applied on top.

### 8.3 Tap path

1. `canCross(localSheet, localLockedRows, color, index)` runs in the click handler. If it fails, do not queue anything. Show the reason in the toast and give the cell `aria-disabled`. An illegal tap must never reach the queue.
2. Append the mutation to `queue`.
3. Append to `moves`.
4. Recompute `localSheet` and re-render. No await on the network anywhere in this path.
5. Kick the flusher.

### 8.4 Undo

The undo button is enabled when a `moves` entry for this game exists with `undone: false` and the game status is `active`.

- If that move is still in `queue` (never sent), delete it from `queue`, mark the `moves` entry `undone`, recompute. Nothing goes to the server.
- If it was already acknowledged, push an `undo` mutation onto `queue` carrying `undoes` describing the exact mark or penalty, mark the `moves` entry `undone`, recompute.

Only one level: the button undoes the most recent not-yet-undone move. Pressing it repeatedly walks backwards through `moves`.

### 8.5 Flush protocol, `lib/sync.ts`

The flusher runs on: a tap, regaining network (`online` event), returning to the foreground (`visibilitychange`), and every 5000 ms while the tab is visible and the queue is non-empty. Only one flush is in flight at a time, guarded by a module-level promise.

```
POST /api/games/<code>/mutations
body: { baseVersion: sheets[code].lastAckedVersion, mutations: queue.slice(0, 50) }
```

Outcomes:

- **200.** Set `serverSheet = res.sheet`, `lastAckedVersion = res.version`, `lockedRows = res.lockedRows`, `gameStatus = res.gameStatus`. Delete exactly the flushed `seq` values from `queue`, not the whole store, since taps may have landed during the request. Recompute. If `res.gameStatus === 'ended'`, stop the flusher and poll once immediately.
- **409 `version_conflict`.** The device is the sole writer of its own sheet, so the only realistic cause is a successful write whose response was lost. Compare `res.sheet` deep-equal against `replay(serverSheet, flushedBatch)`.
  - Equal: the batch was already applied. Treat exactly as a 200. Delete the flushed entries. Show nothing to the user.
  - Not equal: the local view diverged. Adopt `res.sheet` and `res.version` as truth, delete the flushed entries from `queue`, mark the corresponding `moves` entries `undone`, recompute, and show the toast `Your sheet was updated from the server. Some taps were not saved.`
- **422 `mutation_rejected` with `{ index, reason }`.** The server applied none of the batch. Adopt `res.sheet`, `res.version` and `res.lockedRows` as truth. Then:
  1. Delete the offending queue entry at `index` and mark its `moves` entry `undone`.
  2. Re-validate every remaining queued mutation for this game in order against the adopted state with `canCross` / `canPenalty` / `canUndoCross`. Delete any that are now illegal and mark their `moves` entries `undone`.
  3. Recompute and leave the survivors queued for the next flush.
  4. Show a toast naming the reason in plain language. Map: `row_closed` to `Another player closed that colour.`, `not_strictly_right` to `You can only cross a number to the right of your last one.`, `lock_requires_five` to `You need five crosses in that row before you can lock it.`, `max_penalties` to `You already have four penalties.`, `nothing_to_undo` to `There is nothing left to undo.`, `out_of_range` to `That number is not in this row.`
  Preserving the survivors matters, because a long offline batch can contain valid marks in other rows after one rejected mark.
- **409 `wrong_status`.** The game ended or has not started. Poll once, adopt the poll, clear the queue for this game.
- **403 or 404.** Stop the flusher for this game. Clear its `queue`. Show `You are no longer in this game.`
- **Network failure or 5xx.** Leave the queue untouched. Retry with backoff of 1 s, 2 s, 5 s, 10 s, then every 15 s. Never drop a queued mutation on a transport error.

### 8.6 Poll and reconciliation

`GET /api/games/<code>` every **3000 ms** while the tab is visible and the game status is `lobby` or `active`. Pause on `visibilitychange` to hidden and fire once immediately on becoming visible. Send `If-None-Match` with the last ETag and treat 304 as no change. Stop polling once status is `ended`.

On a 200 response:

1. Write the response into `snapshots[code]`. Render every **other** player straight from it. Opponent state is always server truth. There is nothing local to reconcile there.
2. Update `lockedRows` and `gameStatus` from the response.
3. For **this player's own sheet**, use `sheets.version` as follows:
   - `res.you.version === lastAckedVersion`: the server agrees with what we last acknowledged. Do nothing to `serverSheet`. The queue continues to sit on top.
   - `res.you.version < lastAckedVersion`: a stale read, possible with connection pooling. Ignore it entirely.
   - `res.you.version > lastAckedVersion` **and the queue for this game is empty**: adopt the server sheet and version. This is the normal path after a flush response was lost.
   - `res.you.version > lastAckedVersion` **and the queue is non-empty**: do not adopt yet. A flush is either in flight or about to run and will reconcile through 200, 409 or 422. Adopting here would race the flush and could drop a queued tap. Let the flush own it.
4. If `res.game.status === 'ended'`, stop the flusher and the poller, discard any remaining queue for this game, and render `GameOver` from `res.standings`.

`sheets.version` is optimistic concurrency and a safety net, exactly as the intent says. It is never used to merge two writers, because there is only ever one writer per sheet.

### 8.7 Service worker, `public/sw.js`

Plain JavaScript, no bundler, no imports. Cache name `qwixx-shell-v1`.

- **install:** precache `/`, `/rules`, `/offline`, `/manifest.webmanifest`, `/icons/icon-192.png`, `/icons/icon-512.png`. `skipWaiting()`.
- **activate:** delete caches whose name is not `qwixx-shell-v1`. `clients.claim()`.
- **fetch:**
  - Any request whose path starts with `/api/`: **network only. Never cached, never stored.** Return the network response or let it fail.
  - Navigation requests: network first, fall back to cache, fall back to `/offline`.
  - `/_next/static/*` and `/icons/*`: cache first, then network, then put into cache.
  - Everything else: network only.
- **sync event with tag `qwixx-flush`:** open the `qwixx` IndexedDB directly with the raw API, read `sheets` and `queue` for the last game in `meta.lastGame`, and POST the same body as section 8.5. **Handle only the 200 case:** on 200 apply the same writes as the page does. On any other status or on any error, leave the queue and the sheet untouched and let the page reconcile the next time it opens. Duplicating only the happy path keeps the reconciliation logic in one place, which is `lib/sync.ts`.
- iOS Safari does not implement Background Sync, so the page-level flusher in `lib/sync.ts` is the primary path and the `sync` handler is an enhancement. Do not move any logic out of `lib/sync.ts` on the assumption the service worker will run.

The service worker file must contain no Supabase URL, no key, and no reference to any environment variable.

## 9. Mobile layout at 390 px

The old app put 11 numbers plus 2 controls into one flex row of 13 columns and was untappable on a phone. Do not repeat that.

### 9.1 The approach

At 390 px viewport with `px-3` page padding, the usable width is 366 px. Each colour row is a **card**. Inside the card the 11 numbers plus the lock cell form a **CSS grid of 6 columns by 2 rows, giving exactly 12 cells**: indices 0 to 5 on the first line, indices 6 to 10 plus the lock cell on the second line. Reading order stays left to right then down, which matches the printed sheet. There is no horizontal scrolling and no pinch to zoom.

```
grid-cols-6 gap-1.5   ->  (366 - 5 * 6) / 6 = 56 px per cell
```

- **Tap target: minimum 48 x 48 CSS px**, set with `min-h-12 min-w-12` on every cell, penalty box, and button. The computed 56 px cell clears it. WCAG 2.2 AA requires 24 x 24; 48 is the comfortable phone standard and is what we ship.
- Cell height is fixed at 56 px so a cell never reflows when it is crossed.
- At `sm:` (640 px) and above, the grid becomes `sm:grid-cols-12` and the row renders as one line of 11 numbers plus the lock, matching the physical sheet. **Write the mobile grid first. The `sm:` rule is the override.**

### 9.2 Card structure per row

```
[ card ]
  header line:  [glyph] RED  2 to 12          [lock chip]      [21]
  grid line 1:  2   3   4   5   6   7
  grid line 2:  8   9   10  11  12  [LOCK]
```

The header line carries the row name in text, the direction in text (`2 to 12` or `12 to 2`), the lock state, and the row score. All four are text, not colour.

### 9.3 The rest of the screen at 390 px

- Sticky header: game code, sync status, a `Rules` link. Height 48 px.
- Four row cards stacked vertically.
- Penalty card below them: four boxes at 64 x 64 px in a row, plus the label `Penalties` and the running `-5` per box.
- `OpponentList` below that: one compact strip per other player, showing display name, total score, penalty count, and four small per-row cross counts. Read-only. Collapsed to a single line each by default with a disclosure for the row detail.
- Sticky bottom bar, height 64 px, `env(safe-area-inset-bottom)` respected: your total on the left, `Undo` button on the right at 48 px tall.
- Total vertical budget on a 390 x 844 screen: header 48, four cards at about 120 each is 480, penalty card 96, bottom bar 64. That is 688, which leaves the opponent list reachable by a short scroll. Do not add anything else to the game screen.

### 9.4 Non-colour cues, one per row

Colour is never the only signal. Every row carries **three** non-colour cues: a shape glyph, a text label, and a stated direction.

| Row | Glyph (`RowGlyph.tsx`, inline SVG, `aria-hidden="true"`) | Text label | Direction text |
|---|---|---|---|
| red | filled circle | `RED` | `2 to 12` |
| yellow | filled triangle pointing up | `YELLOW` | `2 to 12` |
| green | filled square | `GREEN` | `12 to 2` |
| blue | filled diamond | `BLUE` | `12 to 2` |

Cell states, none of which rely on colour alone:

| State | Visual | Semantics |
|---|---|---|
| open | number, plain border | `<button aria-pressed="false">`, accessible name `Cross off red 7` |
| crossed | number with a drawn X stroke over it and a heavier border | `aria-pressed="true"`, accessible name `Red 7, crossed off` |
| blocked (left of the rightmost cross, still open row) | number at 40 percent opacity with a horizontal strike | `disabled`, accessible name `Red 5, no longer available` |
| closed (colour closed game-wide) | whole card dimmed, a padlock glyph and the text `Closed by <name>` in the header | every cell `disabled`, card has `aria-describedby` pointing at that text |
| lock cell, unavailable | padlock glyph plus the text `5 needed` | `disabled`, accessible name `Lock red, five crosses needed` |
| lock cell, available | padlock glyph plus the text `Lock` | `aria-pressed="false"` |

Further accessibility requirements, all gates:

- Every interactive element has a visible focus ring: `focus-visible:outline-2 focus-visible:outline-offset-2`.
- Text on a colour tint uses the paired ink token from section 10. Every pair clears 4.5:1. Never white text on the saturated row colour.
- The toast region is `role="status" aria-live="polite"`. The game over panel is `role="status"` and receives focus on mount.
- The score total updates inside an `aria-live="polite"` region so a screen reader announces it.
- Framer Motion is limited to a cell scale on cross and a fade on the game over panel. Both are wrapped in `useReducedMotion()` and disabled when the user prefers reduced motion.
- The page must be usable at 320 px width without horizontal scroll. At 320 px the 6 column grid gives 44 px cells, which is below the 48 px target, so add `min-[360px]:` nothing and instead let cells shrink to `min-h-11` under 360 px. State in the README that 360 px is the supported floor and 320 px is degraded but functional.

## 11. Build-time proof that no Supabase key reaches the browser bundle

`scripts/check-no-secrets.mjs` runs after `next build` as part of the `build` script. A leak fails the build with exit code 1.

Behaviour:

1. **Refuse to pass vacuously.** Read `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `QWIXX_COOKIE_SECRET`, `QWIXX_IP_HASH_SECRET`. If any is missing or shorter than 8 characters, exit 1 with `Cannot verify the bundle because <VAR> is not set.` A check that silently skips is worse than no check.
2. **Assert no public env leak path exists.** Scan every `.env*` file present and the `process.env` keys used in source. If any key begins with `NEXT_PUBLIC_`, exit 1. This project has no legitimate `NEXT_PUBLIC_` variable.
3. **Scan the client bundle.** Recursively read every file under `.next/static/` plus `public/sw.js`, as UTF-8. For each file test against this list of needles:
   - the exact value of `SUPABASE_SERVICE_ROLE_KEY`
   - the first 24 characters of `SUPABASE_SERVICE_ROLE_KEY`
   - the exact value of `SUPABASE_URL`
   - the exact value of `QWIXX_COOKIE_SECRET`
   - the exact value of `QWIXX_IP_HASH_SECRET`
   - the literal strings `service_role`, `SUPABASE_SERVICE_ROLE_KEY`, `supabase-kong`, `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9`
4. **Scan the prerendered HTML** under `.next/server/app/` for `*.html` and `*.rsc` files with the same needles, because a value inlined into RSC payload also reaches the browser.
5. On any hit, print the file path, the needle name (never the secret value itself), and the byte offset. Exit 1.
6. On a clean pass print `No Supabase credential found in the client bundle. Checked <n> files.` and exit 0.

Additional static guard, enforced by review and by the script's step 2: `lib/supabase/server.ts` is the **only** file in the repo that imports `@supabase/supabase-js`. The script asserts this by scanning `app/`, `components/`, `lib/` and `public/` for the string `@supabase/supabase-js` and failing if it appears anywhere except `lib/supabase/server.ts`.

## 12. `lib/rulesContent.ts` and `app/rules/page.tsx`

The rules, strategy and probability content is carried over from the old app's `expander.py`. The facts are unchanged. The copy is rewritten to the Luwah standard: no emoji, no em dashes, no arrows as punctuation, short active sentences.

Shape:

```ts
export interface RuleSection { id: string; title: string; body: string[] | RuleList[]; }
```

Render with `components/Collapsible.tsx`, a native disclosure pattern: a `<button aria-expanded aria-controls>` and a region. The first section is open by default. Sections in this order and with these ids and titles:

1. `overview` / **Game overview**
2. `how-to-play` / **How to play**
3. `scoring` / **Scoring**
4. `locking` / **Locking a row**
5. `game-end` / **How the game ends**
6. `strategy` / **Strategy**
7. `probability` / **Dice probability**
8. `cheat-sheet` / **Scoring cheat sheet**

Ship this copy verbatim.

**Game overview**
- Players 2 to 5. Ages 8 and up. About 15 minutes.
- Object: score the most points by crossing off numbers in the four coloured rows.
- Components: six dice, four coloured and two white, plus a score sheet for each player.
- Red and yellow run 2 to 12, left to right. Green and blue run 12 to 2, left to right.

**How to play**
- The active player rolls all six dice.
- Everyone may use the sum of the two white dice.
- The active player may also use one white die plus one coloured die.
- Cross off the matching number in the matching coloured row.
- Numbers must be crossed off left to right in each row. You may skip numbers. You cannot go back.
- You never have to cross anything off.
- If you cross nothing off on your own roll, mark a penalty. Four penalties ends the game at once.

**Scoring**
- 1 crossed number scores 1. 2 score 3. 3 score 6. 4 score 10. 5 score 15. 6 score 21.
- 7 score 28. 8 score 36. 9 score 45. 10 score 55. 11 score 66. 12 score 78.
- Each penalty costs 5 points.
- Final score is the four row scores added together, minus penalties.

**Locking a row**
- To lock a row you must already have at least 5 numbers crossed off in it.
- You must then cross off the rightmost number of that row. That is 12 for red and yellow, and 2 for green and blue.
- You can only reach that number with a coloured die, not the white dice sum.
- The lock counts as one more crossed number when you score the row. Five crosses plus the rightmost number is six crosses, and the lock makes seven, which scores 28.
- Locking removes that coloured die from the game. Nobody crosses anything off in that row again, including you.
- Lock too early and you cut your own scoring short. Lock too late and someone else takes it.

**How the game ends**
The game ends the moment either of these happens.
- Any player marks a fourth penalty.
- Two coloured rows are locked.
Then add up each row, subtract 5 for each penalty, and the highest total wins.
If two players tie, the one with fewer penalties wins. If they still tie, the one with the most numbers crossed off in a single row wins.

**Strategy**
- Early on, favour the middle numbers 6, 7 and 8. They come up most often.
- Do not rush. A cross you regret blocks everything to its left.
- Watch which rows the other players are filling.
- Mid game, pick the rows you can realistically finish and push those.
- Late game, defend. Locking a row denies it to everyone else.
- 2, 3, 11 and 12 are rare. Do not wait for them.
- Green and blue often score less than red and yellow because they run downwards from 12.
- Taking a penalty is sometimes better than crossing off a number that blocks your row.

**Dice probability**
Two white dice, 36 outcomes.
- 7 comes up 6 ways out of 36.
- 6 and 8 come up 5 ways each.
- 5 and 9 come up 4 ways each.
- 4 and 10 come up 3 ways each.
- 3 and 11 come up 2 ways each.
- 2 and 12 come up 1 way each.
So 6, 7 and 8 are the numbers to build around, and 2 and 12 are the ones to plan for rather than wait for.

**Scoring cheat sheet**
Render as a two column table of crosses to points, 1 through 12, using the values above. Below it, these reminders as a list.
- Cross off left to right only.
- You need 5 crosses in a row before you can lock it.
- The lock counts as an extra crossed number.
- Four penalties ends the game.
- Two locked rows ends the game.
- Each penalty costs 5 points.
